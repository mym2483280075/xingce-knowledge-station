## 界面设计约定（2026-09-20 重构）

改界面之前先读这一节，否则很容易又把样式写回「每个页面一份」。

**三层结构**

1. `design-tokens.css` —— 只有变量和极少量基础类。颜色一律 `--xz-*`（表面 / 文字 / 线条 / 语义色），
   主色派生层是 `--accent-soft / --accent-soft-2 / --accent-line / --accent-ink / --accent-ink-2`。
2. `板块页样式.css` —— 21 个板块页共用的骨架与组件。**组件里禁止写十六进制颜色**。
3. 板块页 `<style>` —— 只留该页独有的组件（`.fx` / `.mm` / `.vnav` / `.gw-*` / `.slot`…）与
   三行主色声明（`:root{--primary;--primary2;--accent}`）。这几行是调色板本体，**不要**换成令牌。

**暗色模式**只做一件事：`html.xz-dark` 上换一组变量值。任何「写死的颜色」都会在夜晚模式里露馅，
所以新增样式时先在令牌里找一遍，找不到就补一个语义令牌，而不是写 `#xxx`。

**布局约定**

- 目录（`nav.toc`）在外壳 ≥1000px 时固定在正文左侧；≤1000px 自动收起，工具条出现「目录」按钮（由 `板块页脚本.js` 插入）。
- **正文栏宽度跟着设备走**：`--measure` = `clamp(46em, 74vw, 84em)`
  （小屏保底 46em，中间吃掉可用宽度，超宽屏封顶 84em 免得一行 100+ 个汉字）。
  要调宽窄只改 `design-tokens.css` 里这一条；`.layout` 的列定义不要再写死宽度。
  纯文字页（模考材料用的 `.wrap`）另设 74em 上限——没有表格和网格消化宽度，行太长最难读。
- 「演算」按钮固定在右下角（`bottom:16px`），「回到顶部」让位到 `bottom:72px`，两者不要重叠。
- 搜索是**命令面板**（`⌘K` / `Ctrl+K` / `/`），不是顶栏内联下拉；空查询时列快速跳转，不加载索引。

**首页封面**（2026-10-02 新增）

打开网站先落在封面，不再直接进「常识判断」。封面由 `index.html` 自己渲染（不是 iframe 里的板块页），
所以它**不进搜索索引、也不受 `CACHE_V` 影响**；回封面走侧栏「首页」或左上角品牌区。

- 入口全部现算：五大专区、专区内的板块标签、最近三期模考、统计数字都从 `NAV` / `PAGES` / `MK_SECTIONS` 生成，
  加板块或加期次后封面自动跟上，**不要在封面里另写一份文案清单**。
- 「继续上次」读 `localStorage['xz-last-section']`（沿用主题层的 `xz-` 前缀），写入点只有一个：`openSection()`。
  读回来会用 `PAGES` 校验，板块改名或删除后旧值不会把用户带到兜底页。
- 配色只走令牌：专区色由内联 `--c` 传入卡片，卡片自己派生 `--c-soft / --c-line / --c-ink`
  （**不能**借用 `--accent-*`：那组变量在 `:root` 上就算好了，改 `--primary` 不会重算）。
- 单页专区（日常积累 / 考场流程卡）没有二级条目，卡片用各自的 `slots` 字段（`RJ_SECTION.slots` /
  `LC_SECTION.slots`）渲染只读标签 `.cv-tag` —— 改这两页的槽位时记得同步。

## 新增板块 / 新增内容：固定三步（2026-10-04 起）

```powershell
# ① 新板块（可选）：生成页面 + 登记侧栏 NAV（干跑确认后加 --apply）
node scripts/new-section.js --zone xc --id zcfg --name 政策法规 --desc "法律法规速查" --apply

# ② 填内容：卡片类名用 .kp/.unit（知识点）、.qcard（题目）、.shen（申论大题）、.scard（成绩分析）；
#    材料卡必须带 id="mat-111-115" 这种「起止题号」——详见 操作说明 §7.2 / §7.3

# ③ 一条命令：重建索引 + 自动打缓存版本 + 索引自检
node scripts/refresh-site.js
```

`refresh-site.js` 做三件事，全绿就可以发布：

1. **重建索引**（`scripts/build-index.js` → `assets/search-index.json` 与 `assets/search-full/*.json`）。
   索引是**内容哈希 + 无变化不重写**：只有真的改过的板块才落盘，发布时也只传那几个文件。
2. **自动打缓存版本**：`assets/*.js|css` 的 `?v=` 换成该文件内容的 sha1 前 8 位，
   `index.html` 的 `CACHE_V` 换成全部板块页内容的哈希 —— 不用再手工数「升到第几档」，
   也不会出现「HTML 更新了、脚本还是旧的」。
3. **索引自检**（`scripts/check-index.js`）：板块登记、正文覆盖率、锚点存在性、切片是否齐全、
   词形用例、缓存版本六项；任何一项不过就退出码 1。

搜索词形用例在 `scripts/search-fixtures.json`：**以后加了内容，把你希望一定能搜到的词加进去**
（例如新板块里的一个专名），refresh / 发布都会替你验证。随手查一个词落在哪：

```powershell
node scripts/check-index.js --query 政策法规
```

发布：`publish.cmd`（在 Codex 工作区里是 `.\publish.cmd`）
   流程是「比对差异 → 只提交变化的文件 → 等 GitHub Pages 构建 → 校验线上」；
    **发布前会自动跑一遍 `check-index.js`**，索引没跟上（搜不到新内容）就拒绝发布；
   确实要跳过加 `--skip-index-check`。
    **换过图片扩展名（png/jpg → webp）时要加 `--allow-delete`**，否则线上旧图只会被报告、不会被清掉。
   页面等小文件逐字节 sha256 比对，超过 256KB 的索引文件只比对 Content-Length
   ——本机到 GitHub 全域实测只有 20~35 KB/s（同时刻 Cloudflare 有 200 KB/s），
   把 3.9MB 索引整份下载一遍纯属白等。要全量校验就加 `--verify-full`。
   **网络抗干扰**：发布默认启用 `scripts/netguard.py`——自己用 UDP 问公共 DNS 拿真实 IP，
   绕开 Watt Toolkit 这类加速器写进 hosts 的「域名 → 127.0.0.1」接管，重试时还会换一条 IP。
   实测加速器开着时，加速前 `--check` 是 105.5s 失败，加了这层是 10.8s 成功。
   要按系统解析连接（例如真的想走加速器）就加 `--no-netguard`；
   重试策略是「单次尝试 25s + 换候选 IP + 总时限 120s 兜底」（tree 请求 240s、blob 900s），
   可用 `--tries` / `--api-timeout` / `--api-deadline` 调整。
   下载大文件用 `python scripts\gfetch.py <url> -o 目标路径`（支持断点续传）。

**加了图片 → 转成 WebP**：`python scripts\to-webp.py --apply --force-webp`
（细则见下面「图片约定」；转换器只认页面引用的图，估完价再写盘）

> 发布**不使用 git push**：本机 `github.com:443` 时通时不通，脚本改走 `api.github.com` 的 Git Data API。
> 实测带宽：`api.github.com` / `raw.githubusercontent.com` / `*.github.io` 都是 20~35 KB/s，
> 所以「少传文件」比「压小文件」更管用 —— 索引改成内容哈希就是为这件事。

## 全站搜索的两层索引

为什么不是一个 JSON：全站正文约 120 万字，一次性下完要 1.3 MB gzip；
而绝大多数搜索命中都在标题或当前板块。所以拆两层：

| | 核心索引 | 分板块全文索引 |
|---|---|---|
| 文件 | `assets/search-index.json` | `assets/search-full/<板块>.json` |
| 粒度 | 每张卡片 + 页面说明一条（约 2770 条） | 正文按句子切片（约 4500 片 / 55 个文件） |
| 体积 | 480 KB（gzip 40 KB） | 合计 6.2 MB（gzip 2.1 MB） |
| 加载时机 | 聚焦搜索框即加载 | 「立即批」先加载，见下 |

**立即批 / 兜底批（2026-10-04 起）**：

- 立即批 = 当前正在看的板块 ＋ 标题命中的板块 ＋ 板块名/关键词命中的板块，按 2 并发下载
  （一条都没命中时提到 4）；面板里显示「全文索引 N/55」。
- 兜底批 = 其余板块，立即批下完自动接上（保证全站正文都能搜到），但**只在命令面板展开时下载**：
  面板一关立即停，重新打开自动接着下（队列保留）。慢网络上这条很关键 ——
  以前「搜一下」会在面板关掉后继续把整站索引拖完，抢带宽把翻页/跳转拖慢（用户反馈过）。

**索引覆盖 100% 页面文字（2026-10-04 第二轮）**：

- 卡片正文之外，页头简介 / `.meta` / 模块横幅 / 工具条 / 页脚也算正文（`indexPageText`）——
  搜「行政职业能力测验」这类只在页头出现的词，以前一律搜不到。
- 模考中心页（`sections/每周模考.html`）的期次卡片与「如何新增一期模考」都写在 JS 模板里，
  静态 HTML 只有一个空 `#wrap`：现在单独抽成 `assets/search-full/mk.json` 入库。
- NAV 里的板块说明（sub / cnt / desc / keywords）也会入索引（模考期次的 desc 常写着内容线索，
  例如「资料一“旅游业统计”表」）。

**词形处理（同一轮新增）**：中文检索里最常见的三种“搜不到”都能命中了 ——

| 用户输入 | 原文写法 | 命中方式 |
|---|---|---|
| `第106题` | `第 106 题` | 归一化（去掉空白与标点后比子串） |
| `资料分析 增长率` | 两词不相邻 | 分词 AND（每段都要出现，顺序不限） |
| `旅游业统计` | `旅游业情况统计` | 跳字兜底（按顺序命中、跨度受限） |

命中排序：**标题原样 → 标题归一化 → 正文原样 → 正文归一化（卡内出现次数多的优先）→ 多词全中 →
多词差一个 → 模糊（Fuse）→ 跳字**；板块名/关键词完全一致时置顶为「板块直达」
（例如搜「第十期」「倡议书」）；当前正在看的板块优先。页内搜索一个字没命中时**不筛掉整页**，
只提示「本页未找到」。
模拟考真题（行测各题、申论各小题）也在索引里，命中后按锚点直接跳进对应子页并高亮。
模糊/跳字命中在目标页里没有可高亮的字串时，页面只滚动 + 描边定位，**不筛掉其它卡片**
（否则会看到一片空白，像“跳不过去”）。

**为什么不用现成搜索库**（2026-10-04 调研）：FlexSearch（13.8k★，自带 `Charset.CJK`）
中文子串与多词都能搜，但**没有错别字容错**，导出索引 3.5 MB 且拿不到原文，摘要高亮就没了；
Pagefind（5.5k★）要引 Rust 构建产物、分块索引对「跳到卡片锚点」这套落位改造太大；
MiniSearch / Lunr（6.2k★ / 9.2k★）默认分词对中文不友好，得自己加 n-gram 编码，索引反而更大。
本站的取舍是：**移植成熟做法（归一化 + 分词 AND + n-gram/跳字兜底 + 分层懒加载），
继续用「按板块切片的纯文本索引」**，这样 1.2 MB gzip 左右能覆盖全站 120 万字，且摘要、
锚点落位都不用改。

## 图片约定（2026-10-01 起：一律 WebP）

页面上的位图**一律 WebP**。`.png` / `.jpg` / `.jpeg` 只能作为源素材，不能作为最终页面引用；
转换与引用改写都交给 `scripts/to-webp.py --force-webp`，不要手工改扩展名。

| 源格式 | 编码策略 | 目标 |
|---|---|---|
| PNG | 无损 WebP | 像素完全一致 |
| JPEG | q75–q95 逐档择优（PSNR ≥38 dB 优先，≥35 dB 兜底；仍不达标才无损） | 分辨率不变，体积尽量小 |

- **分辨率不动**：输出宽高必须与原图完全相等，不等直接报错退出。
- **体积最小化**：在分辨率不变的前提下，多档都合格时选体积最小的 WebP；PNG 用无损，JPEG 在 q75–q95 里逐档评估。
- **细线稿保真优先**：有损档连 35 dB 都够不到的（公文格式那几条占格规范长条）改用无损 WebP，宁可文件大一点，也不让线糊掉。
- **严格 WebP**：用 `--force-webp` 转换时，即使无损 WebP 比原图大，最终引用也仍然是 `.webp`；这类图在转换报告里单列，人工复核后继续用 WebP，不保留 `.png` / `.jpg` / `.jpeg` 作为最终引用。
- **旧兜底视为待办**：不加 `--force-webp` 时，`to-webp.py` 仍有“转完更大就保留原格式”的兼容逻辑；报告出现“保留原格式”时，按严格 WebP 要求重新加 `--force-webp` 处理，不能当作已完成。
- 兼容性：线上 `*.webp` 由 GitHub Pages 按 `image/webp` 发出（已实测 200 + 正确 MIME）；
  iPadOS 14 / Safari 14 起原生支持，本站只在 iPad 与桌面浏览器上看，不需要 `<picture>` 兜底。
- 引用改写只换扩展名，URL 里的中文、百分号编码、`?查询`、`#锚点` 原样保留。
- 删原图要显式加 `--delete-originals`；删掉后旧版本仍在 git 历史与线上仓库里，随时可找回。
- **只转被引用的图**：`sections/` 下没被任何页面引用的历史图片（`sl_assets/`、9月7日整卷扫描等）
  原样留着 —— 要清理是另一件事，先确认再删。

## 约定与坑

- **新增板块页**：只要两行 `<link>`（design-tokens + 板块页样式）、一行 `<script src="…板块页脚本.js?v=…">`，
  加上自己的 `:root{--primary…}`；不要复制内联样式与内联脚本。
  页内差异（卡片选择器、按钮有无、答案结构）由脚本自动探测。
- **改了卡片结构**：同步改 `assets/板块页脚本.js` 的 `CARD_SETS` 与 `scripts/build-index.js` 的白名单，
  否则搜索会静默漏内容（不报错）。
- **模考行测页的材料卡**（`.matcard`，资料一～资料四）必须带 `id="mat-111-115"` 这种「起止题号」，
  否则材料正文（统计表、图注、共用题干）进不了索引、也跳不过去。成绩分析页必须引
  `板块页脚本.js`，否则全站搜索跳进去只会停在页首。
- **搜索词形**：索引与查询都走 `wsSig` 归一化（小写、去空白与标点）+ 分词 AND + 跳字兜底，
  改匹配规则时先跑一遍「第106题 / 资料分析 增长率 / 旅游业统计 / 一笔画」这组用例。
  卡片以外的整页正文也会入索引（`indexPageText`），所以新页面不要再把正文塞进 JS 模板里
  （模考中心页是历史例外，已单独用 `indexScriptText` 兜住）。
- **改了板块页**：按上面第 2 条升 `CACHE_V`；`assets/板块页脚本.js` 自身改动时，
  所有页面的 `?v=` 也要一起升。
- **待录入槽位**：页面上的「待录入」卡片会被一起索引，补完内容后重跑索引即可被搜到。
- **性能相关的既有取舍**（改动时别误删）：
  · 计时器只在运行时按「对齐到整秒」的 setTimeout 刷新，页面切后台即停摆；
  · 演算层的画布位图只在进入演算时分配、退出即释放（2x 屏上一张位图约 20MB）；
  · 板块页图片统一 `loading=lazy` + `decoding=async`；
  · 长页面的知识点块用 `content-visibility:auto`，屏幕外不参与排版；
  · 外壳与侧栏是实色面板，不使用常驻 `backdrop-filter` 毛玻璃。
